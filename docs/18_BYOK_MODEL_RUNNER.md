# 内置 BYOK 模型运行器、账号动作与受控无人值守 Agent

本文说明当前 Web 应用内置的 BYOK（Bring Your Own Key）模型运行器，包括管理员
授权、用户个人设置、语言风格分析、回复草稿、固定账号动作、受控无人值守运行及其
安全边界。

## 1. 当前范围

当前能力位于 `bbw_agent`，通过生产 Web 的 `/api/agent/*` 同源接口提供给已登录
用户。它是应用内部模块，不是对外暴露的 MCP Server，也不是允许外部 Agent 自由
调用站内能力的通用插件系统。

当前提供：

- 配置一个用户自有的 OpenAI-compatible 模型连接并测试连通性；
- 从本人已经归档的历史文字消息中提取语言风格；
- 结合指定会话、语言风格和个人写作要求生成回复草稿；
- 在完整授权和逐次确认后执行四类固定社交账号动作；
- 由用户手动发起一次“生成并发送”私信请求；
- 在额外的管理员授权、用户自治策略和部署开关全部开启后，由专用后台 Worker 执行
  三类受控无人值守任务：回复当前仍未处理的入站文字消息、按间隔生成并发布公开文字
  动态，以及对精确白名单目标执行关注或取消关注。

当前明确不提供：

- 对任意事件、任意定时表达式或任意站内资源开放的通用 Agent；
- 任意 HTTP 请求、任意内部 API 调用或浏览器自动化；
- 向模型交付 Web Cookie、Session、上游 Token、账号密码或其他账号凭据；
- 让模型选择未列入固定白名单的动作；
- 图片、视频、转账、实名、资料修改、群管理等账号操作。

后台能力是数据库任务和固定代码路径，不是把账号交给模型自由操作。模型只能为自动
回复和公开文字动态生成文本；是否执行、执行哪一个固定动作、目标是否合法以及何时停止，
均由应用服务端策略决定。

## 2. 门禁模型

所有开关默认关闭。账号处于停用状态时，模型入口和执行能力均按不可用处理。

| 能力 | 必须同时满足的条件 |
|---|---|
| 查看并配置模型运行器 | 账号有效；模型运行器全局开关开启；管理员已给该用户授权 |
| 风格分析与草稿生成 | 上述条件；模型连接有效且已保存 Key；用户主动开启个人模型运行器 |
| 手动执行固定动作 | 上述条件；账号动作全局开关开启；管理员已给该用户动作授权；用户开启个人执行开关；该动作在个人白名单中；完成本次确认 |
| 生成并发送私信 | 手动执行条件；白名单包含“发送私信”；用户额外开启“允许生成后直接发送”；用户手动发起并确认本次请求 |
| 查看并配置无人值守 Agent | 账号有效；模型运行器、账号动作、无人值守 Agent 三项全局开关均开启；管理员已分别给该用户授予三项权限 |
| 后台实际执行 | 上述条件；部署端开启后台调度；个人模型连接已成功测试且个人模型运行器已开启；个人账号执行和自治总开关已开启；任务类型、固定动作、目标、运行时段、频率和预算均在个人策略内 |

未获得模型运行器基础授权时，服务端对 `/api/agent/status` 等入口返回不可用，用户端
不会显示个人模型入口。界面隐藏不是安全边界，所有读写和执行接口都会重新检查服务端
门禁。无人值守区域只有在三项全局开关和三项逐用户授权全部有效时才会返回并显示；未获
自治授权的用户不能通过直接调用接口读取或修改自治设置。

三层能力彼此叠加，后层不能绕过前层：

| 层级 | 管理员门禁 | 用户门禁 |
|---|---|---|
| 模型运行器 | 模型运行器全局开关；逐用户模型权限 | 有效且测试成功的个人连接；个人模型运行开关 |
| 固定账号动作 | 账号动作全局开关；逐用户动作权限 | 个人执行开关；固定动作白名单；自动回复还要求私信自动发送许可 |
| 无人值守 Agent | 自治全局开关；逐用户自治权限 | 个人自治总开关；任务子开关；自治动作白名单；目标、时段、频率、每日预算和失败停机策略 |

`AI_AGENT_BACKGROUND_ENABLED` 是部署端最后一道默认关闭的运行门禁，只控制后台扫描和
执行是否启动，不能替代数据库中的管理员授权和用户设置。

### 2.1 管理端控制

管理接口使用管理端 Session，修改操作必须提交 `3` 至 `500` 个字符的理由：

| 接口 | 作用 |
|---|---|
| `GET/POST /api/admin/byok-model-runner` | 查看或修改模型运行器全局开关 |
| `POST /api/admin/users/{user_id}/byok-model-runner` | 授予或撤销单个用户的模型运行器权限 |
| `GET/POST /api/admin/byok-account-actions` | 查看或修改账号动作执行全局开关 |
| `POST /api/admin/users/{user_id}/byok-account-actions` | 授予或撤销单个用户的账号动作权限 |
| `GET/POST /api/admin/byok-autonomous-agent` | 查看或修改无人值守 Agent 全局开关 |
| `POST /api/admin/users/{user_id}/byok-autonomous-agent` | 授予或撤销单个用户的无人值守权限 |
| `GET /api/admin/users/{user_id}/agent-runs` | 只读查询单个用户的模型运行审计（可按状态/运行类型筛选，不含提示词、密钥与输出正文） |
| `GET /api/admin/users/{user_id}/agent-actions` | 只读查询单个用户的账号动作执行审计（可按状态筛选，不含目标/参数快照） |
| `GET /api/admin/users/{user_id}/autonomy-tasks` | 只读查询单个用户的无人值守任务（可按状态筛选，含 `manual_review` 人工核对项） |

账号动作全局开关依赖模型运行器全局开关；逐用户账号动作授权依赖该用户已经获得模型
运行器授权，且账号未停用。无人值守全局开关依赖前两项全局能力；逐用户自治授权依赖
该用户已经获得模型和动作两项授权。管理端会记录查看、开关变更、逐用户授权和级联撤销
审计。

关闭或撤销时采用以下规则：

- 关闭模型运行器全局开关，会同时关闭账号动作和无人值守全局开关，关闭全部个人自治
  设置，取消尚未开始的自治任务，并处理仍处于活动状态的模型运行记录和排队账号动作；
  已经发往模型服务的请求无法撤回，但返回结果会因后续门禁校验失败而被拒绝使用；
- 关闭账号动作全局开关，会同时关闭无人值守全局开关、关闭全部个人自治设置，并取消
  尚未开始的账号动作和自治任务；
- 只关闭无人值守全局开关时，会保留逐用户自治授权记录，但关闭全部个人自治设置并取消
  尚未开始的自治任务；
- 撤销用户模型运行器授权，会关闭该用户的个人模型运行开关，级联撤销其动作和自治
  授权，关闭个人执行与自治设置，并取消该用户尚未开始的相关任务；
- 撤销用户账号动作授权，会级联撤销自治授权，关闭其个人执行与自治设置，并取消尚未
  开始的相关任务；
- 撤销用户自治授权，会关闭其个人自治设置并取消尚未开始的自治任务；
- 停用账号会使全部门禁失败，同时关闭个人模型、账号执行与自治设置，并撤销动作和
  自治授权。

已经进入 `running` 的账号动作可能已对外产生副作用，因此不会被伪装成
`cancelled`。自治任务进入 `dispatching` 后同样不会被批量取消或重新领取；如果 Worker
在派发阶段失联，任务会转为需要人工检查并使个人自治策略停机。管理员应结合执行记录和
目标账号实际状态判断结果，不能依赖盲目重试。

### 2.2 用户个人控制

获得管理员授权后，用户仍需自行完成以下设置：

1. 保存模型基础地址、模型名称和个人 API Key；
2. 测试连接，并主动开启个人模型运行器；
3. 按需分析本人语言风格，或直接配置个人写作要求；
4. 若需要账号动作，主动开启个人执行开关；
5. 从系统固定动作中逐项选择个人白名单；
6. 若确实接受无草稿预览的风险，再单独开启“允许生成后直接发送”；
7. 若管理员另外授予无人值守权限，用户还需开启个人自治总开关，逐项选择自动回复、
   定时公开文字动态或白名单关系维护，并配置允许运行的固定动作；
8. 为自治策略配置运营目标与内容边界、精确关系目标、时区和每日活动时段、动作最小
   间隔、分类与总量预算、发动态间隔以及连续失败停机阈值。

用户侧自治接口仍使用现有同源登录 Session：`PUT /api/agent/autonomy-settings` 用于保存
个人策略，`GET /api/agent/autonomy/tasks` 只返回本人的最近任务状态。两者都要求完整的
三层管理员授权；未授权时返回不可用，而不是暴露其他用户或系统配置。

个人执行设置发生变化时会递增版本。动作准备、开始和最终派发均校验该版本；在确认后
修改开关或白名单，会使旧请求失效。个人自治策略也具有独立版本；策略变化会取消尚未
开始的旧任务，Worker 在生成前和派发前还会重新核对策略与执行设置版本。

## 3. 模型连接、风格和草稿

### 3.1 BYOK 连接

用户配置的是 OpenAI-compatible Chat Completions 服务。API Key 使用应用的
AES-256-GCM 信封加密体系保存，与用户和连接记录上下文绑定；保存后只返回“已配置”
状态，不回显明文。调用模型时，服务端仅在内存中解密本次所需 Key，并在使用后清空
运行时字段。

模型地址不是通用出站代理。服务端要求 HTTPS、禁止 URL 用户名和密码、查询参数、
片段及 IP 字面量；正式环境要求域名命中 `AI_BYOK_ALLOWED_HOSTS`，且只允许标准
HTTPS 端口。每次调用都会重新解析域名，拒绝内网、本机和保留地址，并将实际 TCP
连接固定到本次校验通过的公网 IP，同时保持原域名的 TLS/SNI 校验。客户端不跟随
重定向、不读取系统代理，并限制连接时间、响应时间和响应体大小。

域名白名单只表示管理员允许系统向该服务发送请求，不代表平台替用户担保模型服务的
隐私、计费、保留或训练策略。用户和部署方仍需自行审核模型服务商。

### 3.2 语言风格

风格分析只选择本人发出的、未撤回的历史文字消息，并排除由模型生成或带 Agent 来源
标记的消息，避免模型输出反复污染风格样本。当前至少需要八条有效样本，最多使用一百
条，每条截断到受控长度。

提交给模型的任务只要求总结语气、句式、词汇、标点、常用表达及建议保持或避免的写法，
明确禁止推断敏感身份、健康、政治、宗教、性取向或财务属性。分析结果保存为用户自己的
风格摘要和结构化特征；这不是通用长期记忆，也不会自行收集事实、联系人画像或账号秘密。

### 3.3 回复草稿

草稿生成读取指定联系人的已归档文字会话，按用户设置取最近 `1` 至 `100` 条有效消息，
结合可选的风格摘要、个人写作要求和本次回复目标形成模型输入。历史消息和用户数据在
提示词中均标记为不可信内容，模型被要求忽略其中索取密钥、改变规则或要求执行操作的
指令。

普通草稿接口只返回文字，不执行发送。生成记录保存运行状态、模型名称、消息数量、字符
数、Token 数、耗时和生成结果，但不保存完整 Prompt、Authorization Header、API Key
或模型服务的原始响应。

## 4. 固定账号动作

模型运行器没有通用工具调用能力。服务端只接受以下四个固定动作标识，并对参数、权限和
目标再次验证：

| 动作标识 | 用户可见动作 | 参数与主要约束 |
|---|---|---|
| `send_private_message` | 发送私信 | 必须指定其他用户和不超过两千字的文字；执行前校验主动私信权限和黑名单 |
| `publish_text_post` | 发布文字动态 | 只接受不超过两千字的文字及 `public`、`followers`、`private` 三种可见范围；当前页面默认使用 `public`；不接受媒体 |
| `follow_user` | 关注用户 | 必须指定其他用户；黑名单关系禁止执行 |
| `unfollow_user` | 取消关注 | 必须指定其他用户；黑名单关系禁止执行 |

动作由服务端调用现有、按当前用户隔离的消息、动态和关系服务。优先使用 Web 本地权威
数据通道；目标尚未迁移且当前用户具有有效外部会话时，才使用已有兼容通道。该过程不会
把外部会话或凭据交给模型，也不会在动作执行期间尝试使用密码重新登录或刷新凭据。

每个动作都使用幂等请求标识。执行审计记录动作类型、状态、审批来源、触发来源、设置
版本和外部结果标识。正文仍保存在消息或动态的权威业务表中；动作审计仅保存正文
SHA-256、字符数等摘要，避免再复制一份明文内容。

## 5. 确认机制

### 5.1 手动固定动作

发送已填写的私信、发布文字动态、关注和取消关注采用两阶段确认：

1. 用户填写动作、目标和内容，客户端调用 `/api/agent/actions/prepare`；
2. 服务端检查当前门禁、个人白名单和目标策略，返回动作摘要及五分钟有效的一次性确认
   凭证；
3. 页面展示将执行的目标和文字，用户再次点击确认；
4. 客户端调用 `/api/agent/actions/execute`，服务端核对凭证是否属于当前用户、是否与
   动作参数及幂等标识完全一致，并以原子方式消费凭证；
5. 在真正产生副作用前，服务端再次锁定并检查全部管理开关、用户开关、动作白名单和
   设置版本。

确认凭证只在 Redis 中保存摘要状态，使用后立即失效，不能改参数后复用。

### 5.2 生成并发送

“生成并发送”只适用于私信。它要求用户已经允许发送私信、主动开启“允许生成后直接
发送”，并在页面填写目标和本次回复目标。页面会明确提示最终文本不会先作为草稿返回，
用户必须对本次请求再次确认。

客户端确认后调用 `/api/agent/replies/send`。服务端在同一个用户发起的请求中生成
回复，再重新检查模型运行状态、账号执行状态、私信白名单、自动发送许可、设置版本和
目标策略，最后通过固定的
`send_private_message` 执行器发送。最终文本和结果只会在执行完成后返回。

直发与手动固定动作的服务端确认方式不同：它不使用 `/actions/prepare` 的一次性凭证，
服务端依据用户已经保存的直发许可、同源登录 Session、本次幂等标识和执行前最终门禁
授权；当前 Web 页面仍会针对每次请求展示风险并要求再次确认。

这里的“直接发送”仍然不是无人值守自动回复。每次直发都必须由已登录用户在页面主动
发起并确认；后台自动回复使用独立的自治授权、个人策略、持久化任务和 Worker 链路，
不会因为用户只打开了直发许可就自动运行。

## 6. 受控无人值守运行

### 6.1 调度与 Worker

无人值守调度默认关闭。只有部署端显式设置
`AI_AGENT_BACKGROUND_ENABLED=true`，Scheduler 才会在现有单领导锁内把固定控制任务
投递到 `agent-control` 队列。专用 `agent-worker` 同时监听 `agent-control` 和 `agent`
队列：控制任务扫描到期的个人策略、创建数据库幂等任务，再只把不透明任务编号投递到
`agent` 队列执行。

控制扫描和执行任务都有批量上限、固定任务编号、数据库唯一幂等键和租约。Worker 每次
只处理一个数据库绑定任务，不恢复浏览器或上游 Provider Session，也不开放外部 Agent
调用接口。模型生成与固定动作执行之间使用一次性派发许可；真正产生副作用前，会在同一
数据库事务中锁定任务并重新检查系统开关、逐用户授权、个人开关、动作白名单、目标和
策略版本。

### 6.2 自动回复

自动回复只扫描本地权威消息库中当前仍是会话最后一条、尚未被回复、未撤回且正文非空的
入站文字消息。任务使用消息稳定标识生成幂等键；生成前和派发前都会重新读取会话头。
如果用户已经回复、收到更新消息、消息被撤回或任务策略发生变化，任务会标记失效，不会
发送模型生成的旧回复。

自动回复还必须同时满足个人执行白名单包含 `send_private_message`，并且用户单独开启
私信自动发送许可。模型只能生成受长度限制的文字；发送仍经过固定私信执行器和目标策略
检查。无人值守 Worker 不恢复浏览器或外部 Provider Session，也不降级到 TIM 直发；只有
Web 本地权威消息事务提交成功，任务才记录为发送成功。事务同时产生的 TIM 兼容投递只是
异步镜像，镜像延迟或失败不会回滚已经成功的本地消息，也不会把本地成功改写为发送失败。

### 6.3 定时公开文字动态

定时动态不是任意 Cron 或模型自定计划。用户配置最小发布间隔、每日时段、时区、运营
目标和内容边界；控制任务到期后按时间槽创建幂等任务。模型只生成一条受长度限制的纯
文字内容，后台固定使用 `public` 可见范围，不接受图片、视频、链接抓取或其他媒体参数。

### 6.4 白名单关系动作

后台关系维护只接受用户逐条填写的精确用户编号，不支持通配符、搜索结果或模型临时选择
目标。自己的账号和当前黑名单目标不能加入配置。Worker 只会在个人账号动作白名单和
自治白名单均允许时，对目标执行 `follow_user` 或 `unfollow_user`；关系动作本身不需要
模型生成内容。关系与动态同样以 Web 本地 canonical 事务为权威结果；面向旧系统的兼容
同步由同一事务写入 outbox 后异步处理，不属于无人值守动作的同步成功条件。

### 6.5 预算、停机与未知结果

个人策略包含每日总动作上限、自动回复上限、动态上限、关系动作上限、动作最小间隔、
活动时段和连续失败停机阈值。超出活动时段或最小间隔时任务只会延后；达到每日硬上限、
权限撤销、策略版本变化或目标不再允许时不会执行副作用。

尚未进入派发阶段的 `queued`、`deferred`、`leased`、`generating` 任务可以在关闭功能或
撤销授权时安全取消。任务一旦进入 `dispatching`，系统不再把它当作可重试任务；如果
无法确认外部动作结果，会记录为 `manual_review`、标记结果未知并停用该用户的自治策略，
等待人工核对。系统不会对可能已经产生副作用的动作自动盲重试。

## 7. 数据与安全边界

一次模型请求可能向用户选定且由管理员允许的模型服务发送以下数据：

- 模型名称和生成参数；
- 风格分析所需的本人历史文字样本，或回复所需的指定会话文字；
- 已保存的风格摘要、个人写作要求、本次目标，或定时动态的运营目标与内容边界；
- 用户的模型 API Key，作为该模型服务的 Authorization 凭据。

模型服务不会收到：

- Web Cookie、Web Session 标识或管理员 Session；
- 上游账号密码、Token、UserSig、Cookie 或已保存原始凭据；
- 可调用站内接口的通用 Bearer Token；
- 通用 HTTP 客户端、浏览器控制权、数据库连接或文件系统权限；
- 可自由扩展的工具列表或任意动作名称。

模型只返回文本或风格 JSON。是否执行账号动作由应用服务端的固定代码路径决定，而不是
由模型获得账号权限后自行调用。模型输出、历史消息、风格样本和用户填写的自治目标都被
视为不可信数据；即使其中包含“忽略规则”“读取密钥”或“调用某接口”等指令，也没有
相应的通用执行能力。

此外，接口使用现有用户 Session、同源检查、请求限流、单用户运行锁、全局并发上限、
幂等键和数据库所有者约束；后台链路另外使用策略版本、任务租约、每日预算和事务内派发
许可。管理变更、连接测试、风格分析、草稿生成、执行设置与自治设置变更均写入审计日志，
自治任务和固定动作结果保存在各自的持久化执行记录中，均不记录 API Key。

## 8. 部署与停用建议

上线前按以下顺序启用：

1. 在 `.env` 配置最小化的 `AI_BYOK_ALLOWED_HOSTS`；
2. 部署 Scheduler 和专用 `agent-worker`，但保持 `AI_AGENT_BACKGROUND_ENABLED=false`；
3. 管理员开启模型运行器全局开关，只给已审核用户授予模型运行器权限；
4. 用户保存并成功测试个人连接，主动开启个人模型运行器；
5. 确实需要账号动作时，再开启独立的账号动作全局开关并逐用户授权；
6. 用户开启个人执行开关，选择最小动作白名单；手动动作继续保留逐次确认；
7. 确实需要后台运营时，再开启无人值守全局开关并逐用户授予自治权限；
8. 用户逐项配置并开启最小自治策略，先使用较低预算、较长间隔和较小关系目标白名单；
9. 完成审计与停机演练后，设置 `AI_AGENT_BACKGROUND_ENABLED=true`，并重新加载相关
   Scheduler 与 Agent Worker 进程配置。

发生异常时，优先关闭无人值守全局开关；这会立即使数据库门禁失败、关闭个人自治设置
并取消尚未开始的自治任务。关闭账号动作或模型运行器全局开关会进一步级联停用后续
能力。只把部署端后台变量改为 `false` 可停止新的控制扫描，但不能替代数据库中的紧急
开关。对已经进入 `dispatching` 或结果未知的外部动作，应检查任务记录、消息、动态或
关系实际状态，不要自动重复执行；停止 Agent Worker 时应保留足够的优雅退出时间。
